# Image Persistence™ — Asset Pipeline

**Purpose:** how to add, replace, or expand the image assets behind Image Persistence Challenge™
(`src/features/tratak-intelligence/`), including how to eventually drop in real, production-quality
photorealistic assets in place of today's placeholder artwork, with zero code changes.

---

## 1. Current state, honestly

Sprint 53 replaced the 2 simple mandalas and 2 legacy human-face images with 7 new, more detailed
placeholder designs (3 mandalas + 4 human-face motifs), each a hand-authored SVG generated by
`scripts/image-persistence/generateAssets.mts` from design data in
`src/features/tratak-intelligence/imagePersistenceAssetKit.ts`.

**These are not photorealistic portraits.** This environment has no image-generation tool — nothing that
can produce actual photorealistic raster faces. The "human faces" here are upgraded abstract/geometric
face-motif art (concentric halo rings behind a stylized silhouette with geometric eye/brow/nose/mouth
marks), the same honest category as the images they replace, not an attempt at likeness. This is stated
plainly so nobody mistakes the placeholder for the real deliverable.

**⚠️ Publicity-rights caution for whoever adds real assets later:** a brief for this feature has asked for
faces "inspired by the look and styling of well-known Indian celebrities." Even with a capable
image-generation tool, deliberately steering generation toward a specific real, identifiable person's
facial structure or styling sits in personality-rights / publicity-rights territory (recognized under
Indian law via passing-off and right-to-publicity precedent) independent of copyright, and most commercial
image-generation providers' own usage policies separately restrict generating recognizable public figures.
**Target general Indian facial-aesthetic diversity (age, gender, skin tone, expression range) — not any
named individual — and get legal/compliance sign-off before shipping real photorealistic assets to
production.**

## 2. Folder structure

```
public/assets/image-persistence/
  human-faces/            "original" (non-inverted) human-face assets
  mandalas/                "original" (non-inverted) mandala assets
  inverted/
    human-faces/           pre-generated negatives, same filenames as above
    mandalas/
  generated/                empty staging folder for future raw AI-generated drops
    README.md
```

Every entry in the live pool (`imagePersistencePool.ts`) has an `src` (original) and, for premium entries,
an `invertedSrc` (pre-generated negative) pointing at the mirrored path under `inverted/`. The exercise
always displays the *inverted* file directly — never a runtime CSS filter — when `invertedSrc` is present.

---

## 3. Naming convention

- Mandalas: `mandala-XX.svg` (zero-padded, e.g. `mandala-01.svg`), same filename in both `mandalas/` and
  `inverted/mandalas/`.
- Human faces: `human-face-XX.svg`, same pattern, in `human-faces/` and `inverted/human-faces/`.
- The pool entry `id` in `imagePersistencePool.ts` matches the filename stem exactly (e.g. id
  `mandala-01` → `mandala-01.svg`) — keep this 1:1 so a file is always traceable from its id and vice
  versa.

## 4. Required asset count (today)

| Category | Count | Why |
|---|---|---|
| Human faces | 4 (minimum 3) | Version 1's daily sequence needs 3 *distinct* faces per day (positions 1, 3, 5) |
| Mandalas | 3 (minimum 2) | Version 1's daily sequence needs 2 *distinct* mandalas per day (positions 2, 4) |

Adding more images beyond these minimums increases day-to-day variety (the selection engine prefers
images not shown in the last 3 days) — there's no upper limit; the architecture already scales to
hundreds of images per category with zero code changes, just more pool entries.

## 5. Resolution (for future raster replacements)

Today's placeholder assets are SVG (vector) — infinitely crisp at any display size, no resolution to
specify. **When real raster (photorealistic) assets are ready**, target:

- **2048×2048px minimum**, square aspect ratio (the session screen renders images inside a square
  container via `next/image`'s `fill` mode)
- Format: `.jpg` or `.webp`, high quality (avoid visible compression artifacts — "no blurry images, no
  pixelation" is an explicit product requirement)
- Centered composition, neutral/plain background (per the brief's own human-face requirement) — the
  after-image effect depends on strong, saturated contrast, not photographic realism

## 6. Inversion workflow

**Do not fake inversion with a CSS filter if a real inverted asset can be provided** — the session screen
prefers a real, pre-generated `invertedSrc` file over the CSS `invert` fallback whenever one exists (see
`ImagePersistenceSessionScreen.tsx`).

### For today's SVG placeholders
`scripts/image-persistence/generateAssets.mts` is the committed, re-runnable source of truth. It imports
the pure design data + `invertHexColor()` from `imagePersistenceAssetKit.ts` and writes both the
"original" and "inverted" SVG for every design — the inverted file's colors are a true, exact per-channel
negation (`255 - channel`) of the original, proven by
`src/features/tratak-intelligence/imagePersistenceAssetKit.test.ts`. To regenerate after editing a design:

```
node scripts/image-persistence/generateAssets.mts
```

### For future raster (photorealistic) assets
No image-processing library exists in this repo (no `sharp`/`canvas`/`jimp`). Two options, in order of
preference:
1. **Generate the negative directly from the same source/seed** the original portrait was generated
   from (e.g. asking the image-generation tool for an explicitly inverted-color version) — this is the
   real, non-approximated equivalent of what the SVG generator does today.
2. **Post-process with a real image tool** (e.g. `sharp`'s `.negate()`, or any standard image editor's
   "Invert Colors" operation) applied to the final chosen portrait — add `sharp` as a devDependency only
   if this path is taken; do not add it speculatively.

Whichever path is used, the result must be an actual negative *file*, not a CSS filter applied at render
time — set it as the pool entry's `invertedSrc`.

## 7. Adding a new image (existing category)

1. Design or generate the original artwork (or extend `imagePersistenceAssetKit.ts`'s design data + rerun
   the generator, for more SVG placeholders).
2. Save the original to `public/assets/image-persistence/<category>/<id>.<ext>` and the pre-generated
   negative to the mirrored `inverted/` path.
3. Add a matching entry to `IMAGE_PERSISTENCE_IMAGE_POOL` in `imagePersistencePool.ts` (`id`, `category`,
   `src`, `invertedSrc`, `alt`, `anchorXPercent`/`anchorYPercent`).
4. Add a matching entry to `IMAGE_PERSISTENCE_OBSERVATION_QUESTIONS` in
   `imagePersistenceObservationQuestions.ts` — a real, verifiable question about the actual artwork (see
   existing entries for the pattern).

No other file needs to change — `selectDailyImagePersistenceSequence` and the session screen are already
generic over pool size within each category.

## 8. Adding a new category (future-ready architecture)

`ImagePersistenceCategory` (`imagePersistencePool.ts`) already includes `flowers`, `sacred-geometry`,
`everyday-objects`, and `animals` — reserved, not deleted, from Sprint 53's pool. The brief also names
"Sacred Symbols" as a future category (a rename/addition to the existing `sacred-geometry` slot, or a new
type-union member — either is a one-line type change). None of these are selected by Version 1's
strict Human-Face/Mandala alternation (`CATEGORY_SEQUENCE` in `imagePersistenceDailySequence.ts`) — a
future version that wants to include them just edits that one array; the pool, selection engine, and
session screen require no other change.
